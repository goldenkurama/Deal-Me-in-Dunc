# Data-model notes

The SQL schema is in `database/migrations/001_initial_schema.sql`.

## Tables

- `users`: credentials and current chip/dunkaroo balances
- `daily_login_grants`: one login grant per user and Eastern date
- `daily_dealer_attempts`: one passcode attempt per user and Eastern date
- `user_items`: permanent ownership of fixed catalog item keys
- `user_equipment`: one nullable equipped item key per cosmetic category
- `game_sessions`: internal hand bookkeeping; not exposed as player history
- `currency_transactions`: append-only balance ledger
- `schema_migrations`: migration runner bookkeeping

## Why there is no `shop_items` table

The shop catalog is fixed and lives in `apps/api/src/config/shopCatalog.ts`. MySQL stores only item keys owned or equipped by a user.

Treat item keys as permanent identifiers after release. Display names and descriptions may change, but changing a key requires migrating existing ownership/equipment rows.

## Defaults

A `NULL` or missing equipment row means:

- use the built-in default for card back, table, music, win sound, and bust sound
- use no decoration for the decoration category

## Time

Timestamps are stored in UTC. The Eastern local date used for daily uniqueness is stored separately as a `DATE` generated by the API using `America/New_York`.
